# Research Audit

A backtest is a claim about a counterfactual, and every backtest is wrong in
some way. This document lists the ways this one could be wrong, what was done
about each, and what remains unfixed. Items marked **OPEN** are limitations,
not oversights.

## 0. The one that dominates everything else

**Update:** real market data has since been run — see
[`reports/final_audit/final_validation_report.md`](final_audit/final_validation_report.md).
69 real, sector-diversified, liquid large-cap US equities, 2017–2026
(166,842 rows via Yahoo Finance), through the exact production pipeline with
zero threshold changes. Result: **0 pairs survived cointegration + BH-FDR +
ADF + half-life + stability screening in 6 of 6 walk-forward windows.** The
production strategy never placed a real trade. This was independently
reproduced and is treated as a genuine negative finding, not a bug (§5 of
the linked report / `statistical_audit.md`).

The rest of this section describes the *synthetic* run that predated the
real-data audit and is kept for context.

Before the real-data audit, no market-data egress existed in the build
environment — Yahoo Finance and Stooq both returned HTTP 403, and the proxy
allowlist covered only PyPI, GitHub, npm and crates. Every performance number
in the original version of this repository was produced on a synthetic
market generated by `statarb.data.synthetic`, which builds spreads from an
Ornstein-Uhlenbeck process.

The strategy assumes spreads mean-revert. The generator makes spreads that
mean-revert. **Measuring profitability under those conditions tests the
implementation, not the hypothesis.** A Sharpe ratio obtained this way carries
no information about whether the strategy would make money, and is reported
only so that the engine's outputs can be checked for internal consistency.

What the synthetic run *does* establish: the accounting reconciles, the
invariants hold, the research funnel recovers pairs it was supposed to recover
and rejects decoys it was supposed to reject, and the monitoring layer fires on
faults that were deliberately injected. Those claims survive the data being
fake. The performance claims do not — and the real-data run above shows the
production strategy has no real-market performance claim to make at all,
because it never traded.

## 1. Look-ahead and leakage

| Risk | Status | How it is prevented | Remaining limitation |
|---|---|---|---|
| Same-bar execution | **Closed** | `apply_execution_delay()` enforces `delay_days >= 1` at config validation; a signal formed on the close of day *t* fills on day *t+1*. Verified by `test_no_same_bar_execution`, which corrupts the signal-date close and asserts the fill price does not move. | Fills use the next open with a proportional slippage charge. Real fills depend on queue position and depth; this model cannot represent that. |
| Future data in rolling statistics | **Closed** | Rolling betas and z-scores use closed-form rolling moments over windows ending at *t*. `test_rolling_beta_is_causal` multiplies all future prices by 1.75 and asserts every earlier beta is bit-identical — and separately asserts later betas *did* change, so the test cannot pass vacuously. | A window ending at *t* includes *t* itself. This is not look-ahead (the close is known when the signal is formed) but it does mean the signal uses same-day information, which requires close-to-open execution to be realistic. |
| Pair selection using test data | **Closed** | `select_pairs()` is called per walk-forward window on the training slice only. `ResearchCache` is keyed by `(window_index, selection_mode)` so a cached selection can never leak across windows. | Selection is re-run yearly. A desk would re-run more often; more frequent re-selection would raise turnover and costs. |
| Parameter tuning on test data | **Closed** | Parameters are swept on the **validation** window, frozen, then applied once to test. `MIN_VALIDATION_TRADES = 8` rejects parameter sets with too few validation trades to be meaningful. The parameter heatmap in `reports/figures/11_param_heatmap.png` is explicitly labelled *validation*, not test. | The test windows were run repeatedly during development. Formally this is one researcher-degrees-of-freedom leak that no code can prevent — see §4. |
| Universe construction leak | **Closed** | Liquidity and price filters run inside each training window, not once over the whole sample. | — |
| Survivorship bias | **N/A for synthetic; OPEN for real data** | The synthetic universe has no delistings, so nothing survives that shouldn't. | On real data this is the single biggest trap: a universe built from *currently listed* tickers has already discarded every company that failed. Point-in-time constituent data is required and is not free. |
| Price adjustment | **Partially closed** | Returns are computed from `adjusted_close` throughout; the validator's extreme-return check reads the same column. | Real adjusted-close series are silently restated by vendors after corporate actions, which changes historical backtest results. Not modelled. |

## 2. Statistical validity

| Risk | Status | How it is prevented | Remaining limitation |
|---|---|---|---|
| Multiple comparisons | **Closed, effect not demonstrated** | Benjamini-Hochberg FDR control is applied across all cointegration tests in a window. The funnel prints the expected false-positive count under the complete null (78 tests at α = 0.05 → ~3.9). | **Ablation A2 found FDR made essentially no difference on synthetic data** (Sharpe 3.52 → 3.50). See §5 — this is a null result and is reported as one. |
| Wrong cointegration test | **Closed** | Uses `statsmodels.tsa.stattools.coint`, which applies MacKinnon critical values appropriate to a residual from an estimated cointegrating vector. Running a plain ADF on an OLS residual instead would overstate significance, because it ignores that the residual came from a fitted regression. | Engle-Granger is a two-step estimator and is asymmetric in which leg is regressed on which; pair ordering is fixed lexicographically so results are at least deterministic. Johansen would be the stronger choice. |
| Hedge-ratio asymmetry | **Mitigated** | `static_ols_hedge_ratio()` documents that regressing A on B is not the same as B on A; ordering is fixed upstream so the choice is consistent rather than arbitrary per pair. | The choice is still arbitrary in the sense that neither ordering is "correct". |
| Half-life misinterpretation | **Closed** | `half_life()` returns both the discrete form `-ln2/ln(1+λ)` and the continuous form `-ln2/λ`, and returns NaN when the AR(1) coefficient implies no mean reversion. Verified against known OU parameters to within 20% at three target half-lives. | Half-life estimates on ~750 training observations are noisy; the estimate is used as a coarse filter (2–60 days), not a precision input. |
| Annualisation of Sharpe | **Documented, OPEN** | `sharpe_ratio()` documents that √252 scaling assumes serially uncorrelated returns. | Pairs-trading returns are autocorrelated (positions are held ~10 days), so the annualised Sharpe is **biased upward**. No Newey-West correction is applied. This alone is a reason to distrust the headline number. |
| Hurst exponent misuse | **Closed** | Computed and reported as descriptive only; it never gates pair selection. | — |

## 3. Accounting and execution realism

| Risk | Status | How it is prevented | Remaining limitation |
|---|---|---|---|
| P&L that does not reconcile | **Closed** | 9 accounting invariants run after every backtest, including `ending_equity == start + Σ net_pnl` to floating-point tolerance and `gross_pnl − cost == net_pnl`. All 9 pass on every window. | — |
| Long-short P&L sign errors | **Closed** | The trade ledger records signed quantities per leg and the invariant `no position without a trade record` cross-checks position events against trades (194 events vs 194 implied by 97 trades). | — |
| Sizing bugs breaching risk limits | **Closed — and this found a real bug** | Costs are charged at the fill, so sizing to exactly `limit × pre-trade equity` breaches the limit post-trade by exactly the cost. Sizing now targets `equity_now − cost_model.charge(gross_intended)` and equity is recomputed per candidate within a bar. Peak post-fill gross/equity is now exactly 1.0000 against a 1.00 limit. | — |
| Mark-to-market exposure drift | **Reported, not enforced** | Pre-trade limits are a hard invariant; drift in existing positions between bars is reported as a monitoring statistic (3 breach days, peak ratio 1.00955 in the 2020 window) rather than being treated as a violation. | A real desk would either de-lever intraday or accept the drift explicitly. This engine accepts it and reports it. |
| Transaction costs understated | **Partially closed** | Commission and slippage are proportional to traded notional and swept from 0 to 40 bps; the edge survives the whole range on synthetic data. | The model does **not** capture market impact, borrow cost on the short leg, financing, or the fact that liquidity dries up exactly when stops fire. All four bite hardest in the scenario the strategy most needs to survive. |
| Unfillable trades | **OPEN** | — | Every order is assumed filled in full at the next open. No volume cap, no partial fills, no gaps through stops. |

## 4. Researcher degrees of freedom

This is the category that no test suite can close.

The walk-forward protocol is honest about train/validate/test separation *within
a run*. It cannot undo the fact that the test windows were executed many times
during development while bugs were being found and fixed. Every look at test
data is a small overfit, and there is no mechanism here that prevents it.

Concretely, the following were chosen by the author rather than by the data:
the correlation pre-filter of 0.6, the half-life band of 2–60 days, the
stability threshold of 50%, the parameter grid boundaries, the 60-symbol
universe size, and the choice to run six windows. Different choices would give
different numbers.

The only real defence is out-of-sample data that has never been touched, which
in this environment does not exist.

## 5. Where the evidence contradicted the hypothesis

Three ablation results did not come out the way the design predicted. They are
reported here rather than buried because a study that confirms everything it
set out to confirm is usually a study with a bug in it.

**FDR control had no measurable effect (null result).** Removing Benjamini-
Hochberg moved Sharpe from 3.52 to 3.50 and added 14 trades. The reason is
visible in the generator: true pairs have median cointegration p = 0.0044 and
decoys have median p = 0.2924, so the two populations barely overlap and a raw
α = 0.05 threshold already separates them. FDR control is insurance against the
regime where signal and noise *do* overlap, which is real markets, not this
generator. The correct conclusion is that this ablation **cannot** measure the
value of FDR control, not that FDR control is worthless.

**Stability screening made performance worse (falsified).** Removing the
rolling-stability screen *raised* Sharpe from 3.52 to 3.98 and nearly doubled
cumulative return (0.47 → 0.83). The hypothesis was that screening removes
pairs whose relationship broke mid-sample and should therefore help.

The ablation is confounded, and the confound is my design error: the screen
halves the book from 20 pairs to 10, so it conflates "screening quality" with
"breadth". More pairs means more independent bets means higher Sharpe from
diversification alone. Max drawdown also doubled (−1.02% → −2.08%), which is
consistent with the surviving explanation that the unscreened book is simply
larger and more exposed. To isolate the screen's effect the comparison would
need to hold pair count fixed and vary only *which* pairs are admitted. That
experiment has **NOT** been run. Additionally only 6 of 48 labelled pairs are
regime-break pairs, so the screen is defending against a small minority while
costing half the breadth.

**Rolling hedge ratios were catastrophically worse (strong, but explained by
the generator).** Switching from a static training-window beta to a rolling
re-estimated beta collapsed Sharpe from 3.52 to 0.23, cut trades from 491 to
216, quadrupled max drawdown (−1.02% → −4.08%) and dropped the hit rate to
0.52 — a coin flip.

This is a clean bias-variance demonstration, and the reason is in the ground
truth: **the synthetic generator uses a constant β.** Rolling re-estimation
therefore adds pure estimation noise to a parameter that genuinely does not
move, and the spread definition shifts underneath the z-score every day. On
real data betas do drift, so this result would attenuate or reverse; it should
be read as "rolling betas are only worth their variance cost when beta actually
moves", not as evidence against rolling betas in general.

**Risk limits cost almost nothing and bound the tail.** Removing them changed
cumulative return by 0.5 percentage points and Sharpe by 0.01, but let peak
gross exposure run to 110.6% of equity versus exactly 100.0% with limits on.
That is the correct argument for limits: they are close to free in the mean and
they bind in the tail.

## 6. What would have to be true for the results to be trusted

1. Real point-in-time price data with delisted names included.
2. A test period never examined during development.
3. Cost assumptions validated against actual fills, including borrow.
4. A Newey-West or block-bootstrap correction on the Sharpe standard error.
5. The stability ablation re-run holding pair count fixed.
6. Capacity analysis: at what AUM does the strategy's own impact eat the edge?

None of the six has been done.
